Multigraffiti
=============

A multi-user version of Graffiti: each drawing has its own URL, and only
connected users can draw. It is the program of the tutorial "Traditional
web interaction in a client-server app"
(https://ocsigen.org/tuto/latest/misc.html).

Instructions
------------

This project was initially generated by `eliom-distillery` as the basic
project `graffiti`. The server side of the application is an Eliom module
(library `graffiti`). It runs either in your own executable, which links
Ocsigen Server as a library, or with the `ocsigenserver` command and a
configuration file.

Generated files
---------------

The following structure has been generated by eliom-distillery:

 - app/
   This directory contains the main application code.
   *graffiti.eliom* registers the Eliom services.

 - app/main/
   This defines your own executable, which links Ocsigen Server as a library,
   configures it and runs the application. It's an alternative to the
   ocsigenserver command and its configuration file.

 - graffiti.conf
   The configuration file for the ocsigenserver command, which loads the
   Eliom module dynamically, as an alternative to your own executable.
   Feel free to remove whichever of app/main/ or graffiti.conf you don't
   use.

 - lib/
   The modules of the application: common.eliom (shared), client.eliom
   (client side) and server.ml (server side). In this library, modules have
   the same names on the server and the client.

 - static/
   Put your CSS or additional JavaScript files here.
   Update the copy rule in *dune* to make local runs work.

 - dune
   Dune is the build system for OCaml. This file defines rules for updating
   the local/ directory and for installing the files to be served.

 - dune-project
   This file defines the project's OCaml dependencies. After modifying this
   file, run *dune build* to update graffiti.opam.

 - local/
   This directory contains the server state (logs, database, command pipe, and
   the compiled client side code) when running locally. Do not put anything
   here manually.

Installing the dependencies
---

Install the opam packages that the project depends on:

    $ opam install --deps-only .

*dune build* reports the libraries and tools that are missing, but not the
packages that Ocsigen Server loads only when it starts, such as the storage
backend given in graffiti.conf.

Running locally (your own executable)
---

To run your application locally:

    $ dune build
    $ dune exec graffiti

The first command updates the generated files in local/ and the second runs
the application.

Running locally (with the ocsigenserver command)
---

To run your application locally:

    $ dune build
    $ dune exec -- ocsigenserver -c graffiti.conf

The first command updates local/ and builds the findlib libraries that
ocsigenserver will look up. The second command spawns ocsigenserver, using Dune
to set up the environment for the local project.
